SPINEVISION FIREBASE AND FIRESTORE ECOSYSTEM UPDATE
PROJECT: spine-vision-en691p

OBJECTIVE:
Update and regenerate the complete Firebase and Firestore ecosystem for SpineVision using the navigation structure and task list provided.

NAVIGATION STRUCTURE ALIGNMENT:
The following models and schemas are mapped to the primary navigation tabs:
DashVision: analytics, sales, user settings.
OmniVision: scans, library (acquisition).
NexusVision: library, listings, bundles, sets, wishlists, refurbish.
OperateVision: sales, crm, amazon, tax.
AssistVision: support, membership.

14 FIRESTORE DATABASE SCHEMA (LOGICAL)
- users: Global profiles and membership status.
- library: Master book inventory per user.
- listings: Marketplace listings (Amazon, eBay, etc.).
- scans: History of all OCR/AR scans (Thrift, Shelf, Spatial).
- crm: Buyer records and interaction history.
- sales: Financial transactions and profit/loss data.
- analytics: Periodic snapshots for dashboard graphs.
- tags: Categorization taxonomy (Global + User).
- bundles: Multi-item listing groups.
- sets: Series and volume tracking.
- wishlists: Items targeted for sourcing.
- refurbish: Restoration task tracking.
- support: Help desk tickets and FAQ.
- membership: Tier-based access control data.

23 FIRESTORE INDEXING STRATEGY
- listings: user_id (ASC) + status (ASC) + date_listed (DESC)
- scans: user_id (ASC) + timestamp (DESC)
- sales: user_id (ASC) + date_sold (DESC)
- library: user_id (ASC) + isbn (ASC)
- crm: user_id (ASC) + total_spent (DESC)

24 DATA RELATIONSHIP MAP
- users (1) -> library (N)
- library (1) -> listings (N)
- listings (1) -> sales (1)
- crm (1) -> sales (N)
- scans (1) -> library (0..1)

25 DATA VALIDATION RULES
- Prices must be non-negative.
- ISBNs must be valid 10/13 formats.
- Required: user_id on all user-specific subcollections.
- Statuses must be from defined enums.

26 DATA MIGRATION STRATEGY
- version field on all documents.
- Background worker (Orchestrator) for bulk updates.
- Incremental migration on document read.

34 FIRESTORE SECURITY RULES BLUEPRINT
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{allPaths=**} {
      allow read, write: if request.auth.uid == userId;
    }
    match /support/{ticketId} {
      allow create: if request.auth != null;
      allow read: if request.auth.uid == resource.data.userId || isAdmin();
    }
    match /metadata/faq { allow read: if true; }
  }
}
